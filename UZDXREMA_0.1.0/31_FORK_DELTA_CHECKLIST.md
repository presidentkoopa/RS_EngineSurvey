# Fork-delta checklist for the 90 Hz plan (anti-drift)

Companion to `30_GAMEPLAN_90HZ.md` (the plan: budgets, waterfalls, milestones M0-M14, owner decisions D1-D15). This file
is what an implementer works from, one row at a time. Rows merge and de-duplicate the seven fork-delta reports
(`work/fork/A_sim.md` [A], `B_modlist.md` [B], `C_frame_xr.md` [C], `D_vulkan_gpu.md` [D], `E_render_lane.md` [E],
`F_monster_stack.md` [Fm], `G_use_the_machine.md` [G]); report IDs are kept. Trees: [F] `/home/claude/uzdxrema` @
e84623f (main), [FR] `/home/claude/uzdxrema_renderer` @ abb19af (renderer), [U] stock 5.0.0, [MOD] the owner's mods
(`/home/claude/mods_x/...`, read only), [BDW] BD22 VR Reloaded source (`presidentkoopa/rsq_bd_vr_reloaded`), [RAD]
RS Radiance source (`presidentkoopa/rs_radiance`), [GITD] `mods_x/RSQ_GlowInTheDark`, [M] the owner's measurements
(`rs_enginesurvey/UZDXREMA_0.1.0/10_MEASUREMENTS.md`, bridge runs rr341-rr352). `VK-XR` = [F]
`src/common/rendering/vulkan/stereo3d/vk_openxrdevice.cpp`. Paths without a tag are [F] `src/...` (a bare file name means
the one file of that name outside `_backups/`). Savings are **Inference** with the derivation in the source report row.
**Decision names:** "owner decision N" = `work/OWNER_DECISIONS.md` (binding now); "D<n>" = plan §7 (open until the
owner answers it: a row that names a D waits for that answer).
**Lane tag** at the start of every Item: `[branch · lane · milestone]`. Lanes: `net` netplay lane, `av` avatar lane
(only inside ROADMAP step 3, D11), `sim` the proposed sim lane (exists only after the owner answers D1), `RL` render
lane (`renderer`, off-by-default cvar; merges to `main` only behind that cvar), `read-only` measurement tooling any lane
may land, `owner` his mods/config/launchers (compat copies, never engine code), `run` a measurement with no commit.

## Implementer rules (read before every row)

1. **One row at a time.** Do not bundle rows into one commit unless the row says so.
2. **Read the row's code first**, at the cited lines, on the branch you will commit to. **If the code does not match the
   row** (lines moved, behaviour different, the item already done or done differently): **stop and ask** the owner or
   the lane lead. Do not "adapt" the row.
3. **Measure before and after with the row's named run** ("Done when"). Record both numbers. No run, no Done.
4. **Netplay replay gate for any sim change** (anything that runs inside `G_Ticker`, `TryRunTics`, `MakeConsistencies`,
   prediction, the VM, playsim, events, or mod sim code): `bash tools/netplay/suite.sh` ALL GREEN on the rig, with the
   row's cvar **on and off**; `NETSET=1` when the net mods are involved. Exact rows also need `-benchdemo` GREEN
   (bit-identical hash). Approximate or rule-changing rows need the owner decision named in the row first.
5. **Branch per CLAUDE.md and the row's lane tag:** render lane rows (`RL`) on `renderer`, behind an off-by-default
   cvar, in the render lane's own checkout (`E:\DOOMWork\UZDXREMA_render`, never the avatar lane's tree); every other
   lane on `main`. Never make a new branch unless the owner asks. Before ROADMAP step 3 freezes the suite, sim
   behaviour changes on `main` stay behind **off-by-default** cvars (D1). **ROADMAP order holds:** the avatar lane
   does steps 1, 2, 3 in order and takes its `av` rows only inside step 3 (D11); `sim` rows start only after the
   owner answers D1 (no sim lane exists today); the render lane is on standby before its stage 3 until RL-Q is
   answered. Start a lane by reading `ROADMAP.md`, then the newest root `HANDOFF_*.md` for that lane (render lane:
   `RENDER_LANE_HANDOFF_2026-11-09.md`; netplay `HANDOFF_NETPLAY_2026-11-11.md`; avatar `HANDOFF_AVATAR_2026-11-11.md`).
   **Render lane, owner's absolute rule of 2026-11-12 ([FR] CLAUDE.md, "STICK TO THE PLAN"):** it builds the next
   unbuilt step of `docs/plans/RENDERER_REBUILD.md` / `STAGE2_STATIC_LEVEL_PLAN.md` the way they say. An `RL` row of
   this checklist that is not yet a step there is one line in that plan's "ideas, not scheduled" list until the owner
   moves it into the plan; if a row departs from the written plan, STOP and tell the owner before any code.
6. **Commit by explicit path.** Never `git add -A`. Never commit a pk3. End commit messages with the session's
   attribution lines. Keep the owner's copy `E:\DOOMWork\UZDXREMA` (remote `mine`) and GitHub equal.
7. **Every exe, pk3, bat or cfg the owner may test gets a new name.** `main`: `python scripts\build_named.py <name>`;
   render lane: its own copy (`build_named_render.py`; `build_named.py` has the `main` tree hard-coded), exes
   `doomxr_rend<date><letter>.exe`, bats `RENDER TEST <date>.bat`, bridge requests `rr###` (avatar lane `r###`);
   packs `scripts\pack_as.py <dir> <new pk3>`. Builds, packs and desk boot tests run on the owner's PC through the
   Claude bridge (`tools/claude_bridge/README.md`, "Current state" first). Desk tests only through the bridge's
   `boottest` (or its `benchreplay`); never launch the game yourself. Never rebuild to test where the Linux rig works
   (`bash tools/linux_rig/setup.sh` downloads the prebuilt engine and refuses a mismatched one; the rig cannot install
   packages from a cloud session, but the netplay suite still runs there: look before saying it cannot). Build only
   when engine code changed (`setup.sh build`), then publish it from `main` only; the render lane never runs
   `publish.sh` and leaves `bin/CURRENT` alone. Engine is Vulkan-only; VR is `vr_mode 15` + `vid_preferbackend 1`.
8. **Update the row**: its Status (Not started / Partial / Done) and one dated log line under the table
   (`2026-MM-DD <ID> <what changed> <before → after> <run id> <commit>`).
9. **Never touch files in the row's Don't-touch column, nor the standing list below** (a "—" in that column means
   only this standing list applies). If the row needs one, hand the change to the owning lane (avatar lane:
   `models.cpp`, `r_data/vr_*.cpp`, `hw_sprites.cpp`, `hw_weapon.cpp/h`, the controller/grip half of VK-XR, the
   `VRRig_*` calls in `hw_drawinfo.cpp`; netplay lane: `TryRunTics`, `MakeConsistencies`, prediction, `d_protocol.h`,
   `hw_vrmodes.h/.cpp` (`SuppressVRInput`, read by `G_BuildTiccmd`), `hw_vrwheel.cpp`, anything that writes `handinput`
   or the `xrLast*`/`xrNet*` edge states in VK-XR (RENDER_LANE_HANDOFF_2026-11-09.md §5); owner: his ini, his mod
   pk3s). A symbol read by `g_game.cpp`, `d_net.cpp`, `p_user.cpp` or ZScript is sim, whatever folder it sits in.
10. **STOPGAP rows** are labelled, sit behind a cvar or in a compat copy, and carry a **removal condition**. Remove
    them when it is met; a stopgap is never the reason a permanent row is skipped.
11. **Dynamic resolution and `vr_openxr_render_scale` < 1.0 are not in this checklist** (owner decision 6), not even as
    stopgaps.
12. **Controller data reaches the sim only through `usercmd_t`** (`d_protocol.h`, `UpdateCanonicalMainHandPose` in
    `p_user.cpp`); the renderer may only draw. A row that would add a render→sim path is wrong; stop and ask.
13. Never tell the owner what time it is, never tell him to go to bed or rest, and never comment on his hours,
    schedule, job or life (CLAUDE.md, absolute).
14. **Memory (owner decision 8):** a row that adds memory states its footprint and records T-MEM before and after.
    Footprints from plan §2.3: P1.1/P1.2/F-GPU-7 +40-120 MB host-visible; ST-GPU-2 +64 MB host until P1.4; P9.9a,
    F-MT-1, F-DOD-2/3, F-MT-8 together +50-120 MB host; P8-2/F-SIM-11 +33 MB host; F-VM-6a/b 0 to +50 MB; RL static
    mesh +158-180 MB VRAM (+ the same in host until F-RL-6); P6.B/VR9.a/VR9.b < 15 MB VRAM. 16 GB is shared with the
    OS, the OpenXR runtime and 57 mods.
